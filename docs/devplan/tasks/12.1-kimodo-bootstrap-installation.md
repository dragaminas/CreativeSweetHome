## Goal
Crear la infraestructura reproducible de instalacion de `Kimodo` para diseno
de movimiento con un script dedicado reutilizado por el bootstrap general del
repo.

## Minimal Context
El repo ya tiene un bootstrap declarativo desde `.env` y un patron claro de
instaladores dedicados en `scripts/apps/`. `Kimodo` todavia no existe como
backend soportado en la instalacion general.

Contexto externo verificado el 3 de mayo de 2026:

- la documentacion oficial de `Kimodo` describe instalacion en Linux por
  paquete o por source install, con `Python 3.10+`, `PyTorch 2.0+` y token de
  Hugging Face para el modelo gated `meta-llama/Meta-Llama-3-8B-Instruct`
  durante generacion
- el gist de `Aero-Ex` activo el 2 de mayo de 2026 propone una variante basada
  en `Aero-Ex/kimodo`, un encoder local `Aero-Ex/KIMODO-Meta3_llm2vec_NF4`, un
  wheel separado para `motion_correction`, `bitsandbytes`,
  `transformers==5.1.0` y un parche manual sobre
  `kimodo/model/llm2vec/llm2vec_wrapper.py`

La fase debe aterrizar primero la infraestructura de instalacion y su
integracion al bootstrap. Fuera de alcance por ahora:

- registrar un runner nuevo
- exponer `Kimodo` por WhatsApp o por plugin
- disenar el bridge a `Blender`
- convertir la variante de `Aero-Ex` en baseline sin justificar el desvio
