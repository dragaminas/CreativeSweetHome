## Goal
Definir la infraestructura de planning para una cadena local y
beginner-friendly de `Create rig` sobre modelos humanoides ya
`cleaned/remeshed`, reutilizando `OpenClaw` como orquestador y `Blender` +
`Rigify` como backend principal de rigging.

## Minimal Context
La fase `13` ya fija el prerrequisito inmediato del repo:
`OpenClaw -> Blender cleanup -> Instant Meshes`, con handoff y evidencia bajo
`Assets3D`. Ese output `cleaned/remeshed` es la entrada obligatoria de esta
fase; el rigging no debe abrir otro pipeline paralelo de preparacion ni volver
a absorber el cleanup principal.

El repo ya dispone de:

- contrato canonico de runner con `run_id`, `inputs`, `options`, estados y
  evidencia
- puente CLI seguro `scripts/actions/runner-action.sh`
- wrapper de `Blender` y helpers de Python en background
- bootstrap declarativo y scripts de instalacion bajo `scripts/apps/`
- convenciones de bridge 3D y layout bajo
  `$STUDIO_DIR/Assets3D/<project>/<entity_id>/`

La fase `13` ya queda aterrizada con tasks hoja para runner y dependencias; esta
tarea debe dejar claro que la implementacion posterior del rigging depende de
ese output preparado y de esa base de provision existente.

El gap real pendiente es de planning de infraestructura, no de implementacion
completa del rigging:

- decidir si `Rigify` puro cubre el primer slice o si hace falta un helper
  libre adicional bien justificado
- fijar el contrato `prepared humanoid -> create rig -> validate -> export`
- definir como se detectan deformaciones basicas y cuando se emite `pass`,
  `soft_pass_with_fallback`, `fail_quality` o `blocked_*`
- producir feedback entendible por principiantes sin exigir `Blender UI` ni
  conocimiento de huesos, pesos, restricciones o modificadores

## Required Change
- Documentar la ruta gratuita y Linux-first mas eficiente para rigging humanoide
  beginner-friendly, usando `Rigify` como baseline preferido y justificando
  cualquier helper libre adicional solo si resulta claramente necesario.
- Definir el handoff obligatorio desde la fase `13`: criterios del modelo de
  entrada, evidencia minima requerida, ubicacion esperada de outputs
  `cleaned/remeshed` y senales de `model not suitable for humanoid rigging`.
- Definir el contrato reutilizable de orquestacion para una futura accion
  simple como `Create rig`, incluyendo que `runner_id`, `operation_kind`,
  `inputs` y `options` conviene extender o registrar sin abrir una CLI ad hoc.
- Definir explicitamente la futura ruta canonica de instalacion o audit de
  dependencias de la fase `14`, con script dedicado del repo, variables de
  `.env`, hook al bootstrap central y smoke validation cuando sea posible.
- Particionar responsabilidades de forma explicita:
  `OpenClaw` para orquestacion, archivos, estados, reporting y diagnostico;
  `Blender` background Python para import, armature/metarig, `Rigify`,
  pesos, validacion y export.
- Definir una validacion automatica con poses o animacion simples que cubra:
  levantar brazos, doblar codos, doblar rodillas, rotar cabeza e inclinar
  torso.
- Definir reporting legible para principiantes con mensajes como:
  `rig created successfully`, `possible shoulder deformation issue`,
  `possible knee deformation issue` y `model not suitable for humanoid rigging`.
- Definir la evidencia requerida: input model path, cleaned/remeshed model
  path, generated rigged model path, Blender command log, validation animation
  or screenshots, y un rigging report en JSON o Markdown.
- Definir criterios de fallback y diagnostico cuando el auto-skinning falle,
  cuando la malla sea borderline o cuando el resultado requiera escalado a
  tareas hoja posteriores.
