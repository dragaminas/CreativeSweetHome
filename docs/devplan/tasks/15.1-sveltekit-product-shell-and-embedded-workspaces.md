## Goal
Implementar el shell principal de producto en `SvelteKit` para que la
experiencia primaria del sistema deje de ser la CLI o una UI de terceros, sin
duplicar el contrato canonico de `runner`, `run_id`, evidencia o cancelacion.

## Minimal Context
El repo ya tiene:

- bootstrap declarativo desde `.env`
- contrato canonico de `runner`
- layouts filesystem-first en `STUDIO_DIR`, `Assets3D/` y `Exports/`
- `ComfyUI` como backend principal de imagen y video
- `Kimodo` como backend local instalado por el bootstrap

El shell web nuevo debe respetar esas decisiones:

- `SvelteKit` es la experiencia principal. Usara typescript.
- `ComfyUI` queda encapsulado como engine y no como UI de producto
- `Kimodo` se reaprovecha casi tal cual, pero embebido bajo el mismo dominio
- la UI debe traducir el input humano a contratos consumibles por herramientas
  reales

Fuera de alcance:

- crear un segundo runner HTTP o una taxonomia nueva de estados
- exponer el canvas general de `ComfyUI` como experiencia primaria
- forzar un fork de `Kimodo` si su UI ya resuelve bien authoring de motion
